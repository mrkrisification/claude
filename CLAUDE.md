# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

This is a **Claude Code skills/data workspace**, not a conventional application. There is
no build system, test suite, or lint step. The "code" is slash-command definitions in
`.claude/commands/`, and the bulk of the repo is the Markdown + PDF *data* those commands
read and write under `baselines/`. Work here means running a command's workflow and
producing/updating these artifacts, not compiling software.

Outputs are generated by launching parallel web-search agents and synthesizing their
findings — always work from the command definition's workflow, and cite every factual
claim with a source and date.

## Primary workflow: `/telecom-pulse <country>`

Defined in `.claude/commands/telecom-pulse.md`. Produces a monthly competitive-intelligence
brief for a national telecom market. Supported markets and their operator lists are the
config table at the top of that file: Slovenia, Austria, Croatia, Serbia, Macedonia,
Belarus, Bulgaria. Read the command file before running — the multi-step workflow (load
context → 3 parallel search agents on fixed angles → synthesize → write files → export PDF)
and the exact output templates live there and must be followed verbatim.

### Per-country data layout (`baselines/<country>/`)

Each market is a self-contained directory. The slug is the lowercased country name.

- `baseline.md` — **stable** 18-month-lookback context (market structure, the defining
  structural event, pricing/infra/financials, "what to watch"). Changes rarely; only the
  expensive `--refresh-baseline` path overwrites it.
- `<YYYY>.md` — the **rolling** year log. One `## <YYYY-MM>` section per month, each with
  *Year so far* / *Last 90 days* / *Directional verdict* / *Outlook*. Re-running a month
  replaces only that month's three sections; **never delete prior months' entries**.
- `sources.md` — **append-only** dated source log; deduplicated URLs grouped by search
  angle, primary documents (earnings PDFs, regulator notices) tagged `[PRIMARY]`.
- `<country>-<YYYY-MM>.pdf` — the exported brief sent to the user.

### Key conventions baked into the workflow

- **Baseline vs. year log**: the baseline is the anchor; the year file tracks only what
  changed in the last 90 days against it. Keep that separation — don't fold rolling news
  into `baseline.md`.
- **Directional, not neutral**: the deliverable is an opinion on competitive intensity
  (Intensifying / Stable / Easing), kept under 600 words. Unsourced claims are dropped.
- **Baseline refresh is gated**: only run `--refresh-baseline` (5 angles, 18-month lookback,
  overwrites `baseline.md`) when a structural trigger fires — merger completed/blocked,
  operator entry/exit, spectrum auction concluded, major wholesale ruling. It is the
  expensive path.

### PDF export

Briefs are rendered with **WeasyPrint**, not a headless browser:
`python3 -m weasyprint <html_path> <pdf_path>`. Write the self-contained HTML from the
template in the command file, convert, send the PDF with `SendUserFile`, then delete the
intermediate HTML.

## The `a1-reports/` subproject

`a1-reports/` is a **distinct, self-contained project** with its **own `a1-reports/CLAUDE.md`**
— a knowledge base for A1 Group annual reports (Markdown wiki for narrative + a DuckDB file
for numbers; no embeddings). When working anywhere under `a1-reports/`, that nested CLAUDE.md
governs — read it first; the conventions here do not apply there.
